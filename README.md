# Тестовое задание: оборудование в CRM

Решение оформлено модулем `acme.equipment`, без правок ядра и копирования CRM-компонентов.

## Подход к реализации

1. Функциональность изолирована в модуле `acme.equipment`. Модуль регистрирует события, создаёт HL-блок и устанавливает JS-extension.
2. Оборудование хранится в HL-блоке. Выборка вынесена в репозиторий; CRM-код не зависит от физического имени таблицы.
3. Связь смарт-процесса со сделкой используется штатная — `PARENT_ID_2`. Дополнительное пользовательское поле не создаётся.
4. Вкладка добавляется серверным событием `crm:onEntityDetailsTabsInitialized`. Контент загружается только при открытии вкладки.
5. Компонент фиксирует `DEAL_ID` в обязательном ORM-фильтре. Пользовательские значения фильтра не могут заменить ограничение по сделке.
6. Grid и filter имеют общий идентификатор, серверную пагинацию и whitelist сортируемых полей.
7. Количество оборудования вычисляется `COUNT` по HL-блоку. Денормализованное поле сделки не используется, поэтому синхронизация не требуется.
8. Счётчик запрашивается через Bitrix Engine Controller. До выполнения запроса проверяется право чтения сделки.
9. Вывод в карточке сделки выполняет отдельный JS-extension. Элемент не содержит form controls и визуально выделяется только для пользователя ID 5.
10. Удаление модуля не удаляет HL-блок: бизнес-данные сохраняются.

## Установка

1. Скопировать каталог `local` в корень коробочного Битрикс24.
2. Установить модуль **Оборудование CRM** в `/bitrix/admin/partner_modules.php`.
3. В CRM создать смарт-процесс **«Заявка на оборудование»** и в его связях включить **Сделку**. Штатное поле связи будет иметь код `PARENT_ID_2`.
4. Открыть от администратора:
   `/local/modules/acme.equipment/tools/seed.php?smartTypeId=ENTITY_TYPE_ID&sessid=BITRIX_SESSID`.

Seed создаёт тестовую сделку, связанный элемент смарт-процесса, три записи оборудования и сохраняет `ENTITY_TYPE_ID` в настройках модуля. Создание типа оставлено штатному UI намеренно: прямой вызов внутреннего `Dynamic\TypeTable` обходит настройку прав, категорий и связей и нестабилен между версиями CRM.

## Что где находится

- `local/components/acme/equipment.grid/` — компонент с `main.ui.filter`, `main.ui.grid`, пагинацией и серверной проверкой прав на сделку.
- `local/modules/acme.equipment/lib/CrmIntegration.php` — вкладка смарт-процесса через `crm:onEntityDetailsTabsInitialized`; ID сделки читается из штатного `PARENT_ID_2`.
- `local/modules/acme.equipment/tools/tab.php` — endpoint ленивой загрузки вкладки.
- `local/modules/acme.equipment/lib/Controller/Equipment.php` — Engine Controller, возвращающий количество оборудования.
- `local/modules/acme.equipment/install/js/acme/equipment/deal-counter/` — JS-extension, вставляющий read-only значение после блока «Клиент».

## Подключение скрипта

При установке модуль копирует extension в `/local/js/acme/equipment/deal-counter` и регистрирует обработчик `main:OnProlog`. Только на URL карточки сделки обработчик вызывает:

```php
\Bitrix\Main\UI\Extension::load('acme.equipment.deal-counter');
```

Далее в head добавляется `DealCounter.mount(dealId, currentUserId === 5)`. Extension запрашивает count через `BX.ajax.runAction`, проверка доступа выполняется на сервере. Блок не содержит input/control и имеет `pointer-events: none`; для пользователя `ID=5` добавляется CSS-модификатор подсветки.

## Принятые решения

- Количество не хранится в сделке: это производное значение, запрос `COUNT` исключает рассинхронизацию.
- Вкладка загружается лениво и не замедляет открытие карточки.
- `DEAL_ID` нельзя подменить для чтения чужих данных: и компонент, и AJAX-контроллер вызывают `CCrmDeal::CheckReadPermission`.
- Uninstall сохраняет HL-блок и данные. Удаление бизнес-данных при удалении модуля недопустимо без отдельного подтверждения.

Минимальная версия: коробочный Битрикс24 с CRM API `onEntityDetailsTabsInitialized` (CRM 20.5.500+) и PHP 8.1+.
